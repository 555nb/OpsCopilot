## 2. Linux 底层可观测性与探针机制

不同于常规脚本直接执行高开销的复杂命令，OpsCopilot 的探针直接对接 Linux 内核虚拟文件系统：

1. **CPU 与调度器（`/proc/loadavg` & `/proc/stat`）**：
   - 提取 1/5/15 分钟运行队列长度与进程总数；
   - 实时比对软中断（SoftIRQ）与上下文切换比率，精准区分是计算密集、IO等待还是网络中断被打满。
2. **内存多维解析（`/proc/meminfo`）**：
   - 物理内存不仅看 `MemFree`，结合 `Buffers + Cached + SReclaimable` 准确推导真实 `MemAvailable`；
   - 追踪 `Slab`（内核对象缓存）与 `Dirty`（脏页待刷盘大小），防范因内核 Slab 泄露或磁盘写入阻塞引发的“伪可用”隐患。
3. **内核 OOM 追踪（`dmesg -T`）**：
   - 结构化提取最近被内核 `oom-killer` 终结的进程 PID、内存得分（`oom_score`）与时间戳。
4. **网络协议栈（`ss` & 内核套接字）**：
   - 直接统计 `ESTABLISHED`、`TIME_WAIT` 与 `CLOSE_WAIT` 连接分布；
   - 警惕 `CLOSE_WAIT` 堆积（代码端未关闭连接）与 `TIME_WAIT` 暴涨（端口耗尽风险）。
5. **幽灵文件排查（`lsof +L1`）**：
   - 检索被 `rm` 删除但进程仍然保持文件描述符（FD）打开的大文件，解决“磁盘显示 100% 但 `du` 找不到大文件”的经典 SRE 痛点。

## 3. 安全护栏（Guardrail）与爆炸半径（Blast Radius）引擎

为彻底避免 LLM 生成高危指令酿成生产事故，系统建立了三道安全防线：

### 3.1 风险分级矩阵

| 风险级别 | 危险分 (Score) | 典型指令范例 | 处理动作 |
| :--- | :--- | :--- | :--- |
| **BLOCK** | 100 | `rm -rf /`, `mkfs.*`, `dd if=/dev/...`, `chmod -R 777 /` | **底层硬拦截**：禁止执行，附带阻断原因与合规告警 |
| **HIGH** | 80 | `iptables -F`, `systemctl stop sshd`, `reboot`, `kill -9 1` | **人在回路 (Approval)**：强制二次弹窗确认，生成前置备份与回滚指令 |
| **MEDIUM**| 40 | `systemctl restart <app>`, `sed -i`, `rm -rf /tmp/xxx` | **受控变更**：提示状态可能抖动，提供状态备份 |
| **SAFE**  | 0 | `cat`, `grep`, `top`, `ss`, `df`, `journalctl`, `ps` | **自主运行**：只读探测，允许静默自动化执行 |

### 3.2 爆炸半径评估维度
每次在给出操作建议前，引擎计算以下 4 项核心指标：
1. **网络中断风险（AffectsNetwork）**：是否修改路由表、清空防火墙链或禁用网络接口；
2. **系统守护进程风险（AffectsCoreDaemon）**：是否涉及 `sshd`、`systemd`、`dockerd`、`kubelet` 等核心服务；
3. **不可逆破坏性（IsDestructive）**：是否包含无回收站删除或块设备格式化；
4. **前置可逆性（RollbackAbility）**：是否能够自动生成对应的逆向撤销指令。
